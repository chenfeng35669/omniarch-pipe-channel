# 圆管与平行板槽道：OmniArch 速度预测

本项目研究圆管和平行板槽道中**不同初始速度分布下的流动工况**。给定截面上 128 个节点连续 10 帧的轴向速度，OmniArch 连续预测后 20 帧。推理只用历史速度；解析解用于生成训练样本和测试真值。

## 最终模型与预测误差

两个模型共用 [OmniArch Base v0.4 原始权重（上游下载）](https://bhpan.buaa.edu.cn/link/AA4C3D921A4EC6439B952F161E819F3938)，分别加载适用于圆管和平行板槽道的解码器。下表列出根据验证误差选出的权重（训练种子 17）。

| 模型 | 解码器权重 | 原测试：总速度误差 | 原测试：扰动速度误差 | 换一批轨迹：总速度误差 | 再换采样间隔：总速度误差 |
|---|---|---:|---:|---:|---:|
| 圆管模型 | [pipe_17_increment_rel_long.pt](results/native_posttraining/pipe_17_increment_rel_long.pt) | **0.372%** | 4.42% | 0.430% | 0.935% |
| 平行板槽道模型 | [channel_17_increment_rel_long.pt](results/native_posttraining/channel_17_increment_rel_long.pt) | **0.444%** | 1.83% | 0.437% | 0.690% |

- **原测试**：前两列误差来自同一批预测。总速度误差以真实速度为参照，扰动速度误差以偏离稳态的那部分速度为参照。扰动较小时，同样的预测偏差占扰动的比例更大。
- **换一批轨迹**：在原参数范围内重新抽取初始条件。**再换采样间隔**：沿用这批初始条件，只改变相邻两帧之间的时间。两次都预测 20 帧，因此间隔改变后，预测覆盖的实际时长也会改变。

每组测试包含 48 条速度轨迹，每条记录一种初始条件下速度随时间的变化。误差先按每条轨迹的 20 帧和全部空间节点加权计算，再对 48 条轨迹取平均。

## 方法：圆管与平行板槽道速度预测的监督后训练

我们采用 [OmniArch](https://proceedings.mlr.press/v267/chen25cp.html) 的公开 Base v0.4 预训练权重，分别训练圆管和槽道的速度预测模型。后训练过程中，傅里叶编码器提取速度剖面的空间特征，Transformer 处理各帧之间的时间关系；两者均保留预训练参数，仅更新一维解码器。各阶段仅以解析解生成的轴向速度为监督信号，损失函数不含动量或能量约束项。

### 第一步：单步速度预测微调

圆管和槽道各生成 256 条训练轨迹，每条包含 36 帧速度剖面。初始剖面由稳态速度与扰动叠加而成，扰动最多由四种基本形状组合。训练时从轨迹中随机截取连续的历史帧，历史长度在 10 帧和 15 帧之间交替。模型预测紧接历史窗口的下一帧速度，以截面平均稳态速度 $U_b$ 归一化预测值和真值，最小化两者在 128 个节点上的均方误差。

### 第二步：基于速度增量的三步滚动训练

为刻画相邻帧间较小的速度变化，从第一步选出的权重出发，用解码器预测速度增量，再由增量重建下一帧的速度剖面。对每个模型，预先生成 256 条训练轨迹：其中 128 条沿用四种基本扰动形状；另 128 条采用八种基本形状，以更小的时间间隔记录流动早期的变化。

设 $u_t$ 为时刻 $t$ 的轴向速度剖面。先计算历史窗口内相邻帧的速度差 $\Delta u_t=u_t-u_{t-1}$，按这些速度差的均方根幅值归一化后输入模型。将网络输出恢复到原速度单位，得到下一步的预测增量 $\widehat{\Delta u}_{t+1}$，再按下式还原速度：

$$
\hat u_{t+1}=u_t+\widehat{\Delta u}_{t+1}.
$$

将 $\hat u_{t+1}$ 加入历史窗口，用同一模型继续预测后两帧。损失取三帧**还原后的速度剖面**与对应真值之间的归一化均方误差的平均值。归一化尺度取该样本历史窗口内各帧相对末帧的均方根变化幅度，下限为 $0.01U_b$，以避免近稳态样本的误差被过度放大。每连续预测三帧，更新一次解码器参数。

### 第三步：低学习率续训

以第二步验证误差最低的解码器为起点，在同一批训练轨迹上继续优化三步滚动预测损失。将学习率由 $10^{-4}$ 降至 $5\times10^{-5}$，再更新 320 次；续训前的权重和此后每 80 次更新的权重均参与验证。

**优化与模型选择。** 三个阶段均使用 AdamW，批量大小为 8，权重衰减系数为 $10^{-4}$。选模时输入 10 帧真实速度，连续预测 20 帧，按总速度的相对误差选择权重。第一步使用 12 条独立验证轨迹；第二、三步对两组独立验证数据各取 16 条轨迹（初始扰动分别由四种和八种基本形状构成），将两组平均误差等权合并。

### 各阶段的测试结果

选模完成后，在同一批[测试工况](data/original_high_modes.json)上评估三个阶段的权重。下表列出 48 条轨迹的平均 20 步总速度误差。

| 后训练步骤 | 学习率 | 更新次数 | 圆管总速度误差 | 槽道总速度误差 |
|---|---:|---:|---:|---:|
| 第一步：单步速度预测微调 | 0.0001 | 160 | 4.921% | 3.940% |
| 第二步：基于速度增量的三步滚动训练 | 0.0001 | 160 | 0.423% | 0.516% |
| 第三步：低学习率续训 | 0.00005 | 320 | **0.372%** | **0.444%** |

## 更换采样间隔

### 固定预测时长

这项实验检验采样间隔如何影响同一段流动过程的预测误差。圆管和槽道各选取 48 个新工况，初始扰动由八种基本形状组合而成。

对每条轨迹，各组从同一时刻开始预测，并在相同的四个时刻核对速度：距预测起点分别为 0.015、0.030、0.045 和 0.060（无量纲时间）。每次输入 10 帧历史数据：采样间隔越短，这 10 帧覆盖的时间越短，预测到同一终点所需的步数越多。

| 训练时未用的采样间隔 | 到终点的预测步数 | 圆管总速度误差 | 槽道总速度误差 |
|---|---:|---:|---:|
| 0.00125 | 48 | 0.607% | 0.565% |
| 0.00375 | 16 | 0.094% | 0.137% |
| 0.0075 | 8 | 0.064% | 0.078% |
| 0.015 | 4 | 0.216% | 0.136% |
| **四个间隔等权平均** | — | **0.245%** | **0.229%** |

### 改变训练数据的采样间隔是否有益？

对圆管模型和槽道模型分别做一次对照实验。每次都从同一份最终权重出发，使用相同的训练批次和学习率（0.00005），各续训 320 次。对照组沿用原数据；实验组保留相同的初始条件，只将 256 条训练轨迹中一半的采样间隔改为 0.001–0.020 范围内的新值。预测时，模型只读取速度记录。

每更新 80 次，用原来的两组验证数据检查误差，两组的初始扰动分别由四种和八种基本形状构造。保留两组误差均不高于续训前的权重，再选出在新采样间隔下误差最低的一份。下表为 16 条独立验证轨迹在 4 个新间隔下的总速度误差；斜线两侧依次对应训练种子 17 和 29。

| 模型 | 续训前 | 原间隔续训 | 换间隔续训 |
|---|---:|---:|---:|
| 圆管模型 | 0.145% | **0.099% / 0.111%** | 0.112% / 0.120% |
| 槽道模型 | 0.179% | **0.170% / 0.152%** | 0.179% / 0.158% |

**改变训练时的采样间隔没有带来额外收益。** 两个模型在两个训练种子下的结果一致：沿用原采样间隔时，验证误差更低。槽道模型使用种子 17 时，换间隔组仍以续训前的权重表现最好。因此未对候选权重做独立测试，仍使用原来的最终模型。

## 运行

使用 Python 3.10 和 PyTorch 2.6.0（见 [requirements.txt](requirements.txt)）。克隆仓库后，将上面的 Base 权重（72,000 步，约 1.23 GB）放在 `weights/omniarch-base.pt`；两份解码器已经随仓库提供。程序加载时会校验 Base 和所选解码器的 SHA-256。

```bash
python -m pip install -r requirements.txt
python -m unittest discover -p "test_*.py"
python reproduce.py
```

在本目录运行 `python reproduce.py` 即可复测两个最终模型。只测圆管用 `--geometry pipe`，只测槽道用 `--geometry channel`；如需在 CPU 上运行，加 `--device cpu`。`--mode base` 和 `--mode compare` 分别运行通用 Base 和早期单步微调对照。Base 权重也可通过 `--checkpoint` 或环境变量 `OMNIARCH_CKPT` 指定。重训结果默认写入 `results/reruns/`，不覆盖[最终模型清单](results/native_posttraining/recommended.json)中的权重。

从官方 Base 重新训练最终方案（CUDA）时，依次执行：

```bash
python diagnose_omniarch.py initial --seed 17
python diagnose_omniarch.py post --seed 17 --arms increment_rel increment_rel_long
```
